Step 1

Protect personal data before anything leaves this computer

  1. Patterns find data with a known shape: emails, phone numbers, card numbers and card endings, account numbers, tax IDs (RFC, NIT, CPF, CNPJ) and amounts.
  2. A small AI model running on this computer finds names and addresses, which have no fixed shape.
  3. Each item is replaced by a label such as [NAME_1]. The real values stay in a local file.
  4. A final check looks for anything left. If it finds something, that case is not sent and goes to a person.

Before and after, every case (highlighted: what was found and hidden)

Step 2

Sort each case into a customer pain category and a root cause

  1. An AI model reads only the protected text from step 1.
  2. It picks one customer pain category from a fixed list. It cannot invent new ones: anything new is marked Emerging for a person to name.
  3. It scores the root cause across the 4Ps, shown here as shares of 100%: People (how the agent handled it), Process (internal steps and handoffs), Policy (rules and limits), Product (the app or platform).
  4. Sensitive cases (fraud, locked accounts, legal) and unsure answers go to a person. The rules live in a settings file that can be changed during the session.
